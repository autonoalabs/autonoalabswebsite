# IT and AI starting-point assessment

## Experience

Keep the established dark and gold theme. A wider questionnaire sits beside a live summary on desktop. On phones the questionnaire fills the width and the secondary summary is hidden. Native radio buttons and checkboxes sit inside clickable cards, with visible focus styles and clear selection states. The four progress steps are navigation, not a maturity score.

1. Your goal: primary business outcome and optional number of users.
2. Current setup: hosting environment and existing business tools.
3. Daily work: one process to start with and the desired approval model.
4. Data and priorities: sensitivity and location requirements.

No answers are preselected. Unknown answers are valid. Back and Edit preserve answers; Start again clears only the questionnaire. Future steps remain disabled until visited. Required questions show a field-specific message and receive focus when missed. Native labels, fieldsets and legends expose each question to assistive technology.

## Starting plan

The rules choose a scoped starting activity, explain the next three stages, suggest measures, flag data/approval checks and optionally link to up to two example architectures. A reliability goal prioritises IT foundations. A wholly uncertain visitor gets a systems/process review before a technology shortlist. A request to keep data inside the customer's environment excludes managed AI from the document-assistant shortlist. Generic ERP or CRM choices do not imply SAP or Salesforce.

Example: a Microsoft user seeking document support, choosing sensitive data and an own-environment boundary, sees a self-hosted document-assistant example with explicit access, masked-pilot-data and approval checks. Changing the process to record matching changes the plan and its measures. Report export and email drafts use the same selected answers as the displayed plan.

This is an initial planning questionnaire. It has no backend, external model, system scanner, pricing estimator or numerical readiness score. It cannot establish compliance, security posture, implementation effort or achievable savings. Data location is a requirement to confirm, not a claim about which services are available. The rule set should be reviewed by the delivery team as services and supported offerings change.

## Privacy and handoff

Answers remain in page memory. There are no uploads, local-storage writes or automatic answer submissions. The user can save a text report or open an email draft. The email app handles sending only after the user chooses to send. Browser refresh clears answers. No sign-up is required.

## Architectural basis

Business outcomes and existing systems come before selecting products, following the planning approach described in [Microsoft application modernisation assessment](https://learn.microsoft.com/en-us/azure/app-modernization-guidance/assess/) and [preparing for an AWS Well-Architected review](https://docs.aws.amazon.com/wellarchitected/latest/userguide/preparing-for-a-wafr.html). This questionnaire is an Autonoa Labs design, not a vendor-certified assessment.

## Validation

Eight automated checks cover required questions, unknown-answer discovery, sensitive-data controls, private data boundaries, Microsoft alternatives, reliability/reporting differences, generic ERP handling, and report/stack-link consistency. Browser checks cover forward/back navigation, Edit, reset, changed answers, download contents, email draft contents and linking to an expanded stack diagram. Responsive checks cover desktop, tablet and phone widths.
